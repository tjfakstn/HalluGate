## 9/30 — 모델링 방향 전환: 스트리밍 조기 탐지
- **왜**: 문장 판정기는 **문장이 끝나야** 판단할 수 있어 누출·보류 지연이 구조적으로 남음. 모델링의 연구적 난이도도 보강 필요
- 문헌 조사: 스트리밍 조기 탐지는 Itkin(2026) 선행 연구 존재(재현율 0.24~0.40, 수작업 신호, 시스템 없음). LettuceDetect는 완성 응답만 판정
  → 차별점: **근거를 직접 읽는 강한 점수기 + 오경보 통제 + 실제 게이트웨이**
- `docs/RESEARCH_PLAN.md` 작성 (RQ1~4, 실험 E1~E6)

### E1 — 평가 프로토콜과 기준선
- v1 실행 후 **프로토콜 결함 2건 발견·수정**: 관대 재현율 과대(0.935), 문장 경계 토큰 오배정(18%) → 엄격 기준으로 v2 재실행
- 결과 (ARL₀=100): 문장 끝 판정 재현율 0.474 / 지연 17토큰, 앞부분 재판정(s=8) 0.448 / 9토큰
- 발견: 환각은 대부분 문장 중간에서 시작(첫 토큰 시작 30%), 시작부터 문장 끝까지 중앙값 13.5토큰
- ARL₀=100은 서비스 기준으로 느슨함(멀쩡한 응답 66%에 경보) → 서비스 지표 추가

### E2 — 앞부분 학습 인과적 점수기
- 문장을 여러 위치에서 잘라 "여기까지 환각이 시작됐나"를 학습 (89,262 예시, 발생 직후 가중)
- **사전 기준 충족**: 재판정 s=4에서 **재현율 0.494, 지연 6.5토큰** (문장 끝 판정 0.474 / 17토큰)
- 부트스트랩: 문장 끝 대비 재현율은 같은 수준, **지연 −10.5토큰은 유의**. 같은 재판정 간격 대비 재현율 **+0.07~+0.10 유의**
- 핵심 발견: **재판정을 자주 할수록 기존 모델은 나빠지고 E2는 좋아진다**
- 완성 문장 AUROC도 0.859 → 0.881로 개선. 모델은 드라이브 `selfproject/student_prefix/`
- 한계: 시드 1개, 환각 응답 154개(구간 ±0.08), 학습 곡선이 아직 상승 중
- 주간 보고서: `docs/reports/…5주차.docx` (S2-b 일반화, S3 게이트웨이, 조기 탐지 E1·E2)

## 10/6 — 스프린트: 결과 신뢰도 + 게이트웨이 통합 (진행 중)
- **E4-lite 노트북**: E2를 시드 3개(42, 7, 2026) × 2에폭으로 재학습해 결과 안정성 확인. 사전 기준: 시드 모두 E2 주 기준 충족 + 시드 평균 충족
- **게이트웨이 앞부분 재판정(stride)** 구현 (SPEC §5.1, 테스트 23개 통과)
  - pass: 문장 도중에도 s조각마다 앞부분 판정 → 경보를 일찍 보냄
  - hold: 앞부분이 안전 판정되면 그때까지 쌓인 본문을 먼저 내보냄 → 문장 끝까지 기다리지 않음
  - 대체 판정기(어휘 기반, 판별력 없음)로 RAGTruth 15개 재생: hold 첫 글자 추가 지연 **469 → 78ms**, 글자당 272 → 32ms (판별력 수치는 무의미)
- **측정 지표**: 환각 발생 시점 기준 누출·엄격 재현율·멀쩡한 응답 표시율을 bench에 추가, 가짜 LLM에 GPT 토큰 단위 재생 추가
- **E5-lite 노트북**: B(student_vark, 문장 끝) / E-end(student_prefix, 문장 끝) / E-s4(student_prefix, 4토큰 재판정)를 같은 조건에서 비교. 사전 기준 C1~C4
- **교수님 피드백(5주차 보고서)**: "애초에 전체 문장의 생성 시간을 측정해야 되는 것이 아닌가?"
  - 지금까지의 지연은 가짜 LLM의 고정 속도 기준 → 판정 시간·보류 지연이 실제로 큰지 판단할 분모가 없었음
  - **L1 노트북**: Claude(Haiku 4.5, Sonnet 5.5)와 GPT 2종에 RAGTruth 원래 프롬프트 60개를 공식 SDK로 스트리밍, 응답·문장·4토큰 생성 시간 측정. 사전 점검 P1·P2
  - bench에 `--timing`(실측 속도 재생) 추가, E5-lite 8절에서 실제 속도로 게이트웨이 재측정
  - 6주차 보고서에서 이 질문에 대한 답으로 정리 예정

## 10/7 — 결과: L1(Claude), E4-lite
- **L1 (Claude만, GPT는 크레딧 부족)**: 응답 전체 p50 Haiku 2.1초 / Sonnet 3.2초, 첫 글자 0.43 / 0.87초

  - P1·P2는 **정의대로 미달**: Sonnet이 글자를 몰아서 보내 문장·4토큰 생성 시간이 0에 가깝게 측정됨. 기준은 바꾸지 않고 기록
  - Sonnet은 출력 토큰의 약 30%가 보이지 않고 2개 응답이 빈 응답(숨은 추론 추정, 미확인)
- **E4-lite (시드 3개 × 2에폭)**: **사전 기준 미달** (시드 0/3이 재현율 0.474 미만)
  - 시드 평균 s=4: 재현율 0.459 ± 0.015, 지연 5.8 ± 1.3토큰 (B1 0.474 / 17토큰)
  - 재현됨: 지연 단축, 같은 간격 기준선 대비 재현율 우위, AUROC 개선(0.874 ± 0.003)
  - 재현 안 됨: B1 대비 재현율 우위, 서비스 10% 우위, "자주 재판정할수록 좋아진다" → **E2 주장 범위를 줄임**
  - 검증 최고점이 세 시드 모두 첫 에폭 2/3 지점 → 더 학습해도 이득 없음
  - 결론: 병목은 점수기가 아니라 점수를 경보로 바꾸는 규칙(순차 판정·임계값 보정)
- **E5-lite (게이트웨이 종단 간, 가짜 LLM 속도)**: C1·C3·C4 충족, **C2 미달**
  - hold:4 첫 글자 추가 지연 625 → 94ms (−85%) — 조기 탐지의 시스템 이득이 분명한 곳
  - 대가: hold:4는 안전 판정된 앞부분을 먼저 내보내서 누출이 생김(탐지 응답 중앙값 64자)
  - pass 누출 110 → 81자로 26%만 감소: 서비스 임계값이 높아 일찍 울리지 못함
  - 환각 응답 26개뿐이고 오경보율이 구성마다 달라(8.8~20.6%) 재현율 비교는 참고 수준
  - **8절(실제 Claude 속도, 30개)**: hold 추가 지연 Haiku 229 → 45ms, Sonnet 303 → 53ms (전체 응답의 11~13% → 약 2%). 교수님 질문에 대한 답
  - 빠른 스트림(Haiku)에서 pass:4 판정 p95 30.3ms로 허용치 첫 초과 → 재판정 간격을 속도에 맞춰 조절할 필요

## 10/7 — 다음 모델링 방향과 평가 세트 확장 (R0)
- **왜**: 세 실험이 모두 "AUROC는 오르는데 엄격 재현율은 안 오름"을 보임 → 학습 목표(위치별 독립 분류)와 평가 목표(발생 전 조용, 발생 직후 경보)의 불일치가 병목
- **계획** (`RESEARCH_PLAN.md` §8): R0 평가 확장 → R2 순차 판정 규칙(가변 재판정 간격 포함) + R3 오경보 보장 보정 → R1 발생 시점 학습
- 토큰 단위로 자르는 아이디어의 현재 위치: 고정 4토큰 재판정까지 구현·검증(E1·E2·E5). "가변" 부분은 R2에서 판정 규칙이 다음 판정 시점을 정하는 방식으로 연구
- **분할 재현 중 발견**: 기존 dev 응답의 62%가 학습과 같은 근거 문서 사용(응답 단위 분할이라 assert에 안 걸림)
- **R0 노트북** (`r0_eval_expansion.ipynb`): 근거 문서가 겹치지 않는 cal-L·dev-L(시드 2027), 오염 측정, 판정기 5개의 점수 궤적 저장. 사전 기준 R0-a~c, 이후 주 평가는 dev-L로 결정
- **R0 결과**: R0-a·b 충족(기존 수치 정확히 재현), R0-c 오염 작음(−0.014 [−0.081, +0.051])
  - dev-L(환각 759개)에서 **E2 이득 대부분이 재현 안 됨**: AUROC +0.005, 같은 간격 기준선 대비 재현율 −0.03(차이 없음), B 문장 끝 대비 재현율 −0.05(유의)
  - 탐지 지연 단축은 주로 **앞부분 재판정 자체**에서 나옴(B에 4토큰 재판정만 붙여도 15 → 9토큰)
  - 실패의 대부분은 **발생 전 경보**(B 문장 끝 41.5%), 끝까지 못 잡는 것은 8.4%뿐 → R2·R1의 목표가 정량적으로 확인됨
  - cal-L 보정은 dev-L에 잘 옮겨감(목표 10% → 실제 7.4~9.9%)
- **R2 노트북** (`r2_sequential_rules.ipynb`, CPU 약 15~30분): 임계값·누적합(CUSUM)·연속 초과·평활·학습 규칙(HistGBM, 판정 이력 특징) 52개 후보를 cal-L에서 보정·선택, dev-L에서 대표 규칙 하나로 판정. R3 등각 보정, 가변 재판정 간격, 발생 전 경보 위치 분석, 게이트웨이 판정기 결정 규칙 포함. 사전 기준은 SSOT §6
  - 만들면서 고친 것: 임계값 규칙 보정에 E1의 +1e-6 규칙을 그대로 써야 R0와 정확히 일치(가짜 데이터 smoke에서 발견)
- **R2 결과**: R2-0 충족, **주 기준 미달**, R3 충족, 게이트웨이 student_prefix 유지(서비스 조건 유의)
  - 52개 규칙 중 어느 것도 재현율 0.50대를 넘지 못함. 평활·누적 규칙은 발생 전 경보(41.5% → 20%)를 미탐지(8% → 33%)로 바꿀 뿐 → **병목은 점수기 판별력**
  - 발생 전 경보의 64%는 환각보다 2문장 이상 앞 → 경계 문제 아님. 일반 오경보인지 정답 누락인지는 미확인
  - 서비스 조건: E2 s=4가 B s=4보다 재현율 +0.040 [+0.008, +0.071], 지연 −6토큰 → 지금까지 dev-L에서 유의하게 남은 E2의 이점
  - 등각 보정으로 표시율 ≤ 10%를 dev-L에서 확인(재현율 비용 약 0.02). 가변 재판정 간격으로 판정 26% 절감 가능(보고)
- **이른 경보 사례 검토**(50건, 그룹 가림, LLM 판정): 환각 응답의 이른 경보 중 30%는 정답에 없는 진짜 환각, 17% 애매, 53% 진짜 오경보. 대조군(멀쩡한 응답 경보)은 15% / 20% / 65%
  - RAGTruth 정답 누락이 엄격 재현율을 약 0.08~0.13 깎고 있음(추정) → 절대값 해석에 주의, 비교는 공정
  - 진짜 오경보가 절반 이상 → R1 진행 결정
- **R1 노트북** (`r1_onset_aware_training.ipynb`, A100/L4 권장, 학습 8회): 판정기 학습 목표를 엄격 재현율의 성공 조건에 맞춤 — 창 안 적어도 하나(다중 사례 학습), 응답 안 순위(어려운 음성 채굴), 정답 누락 완화. 대조군 V0(같은 데이터·지점, 이진 분류)로 목표 효과를 분리. 사전 기준은 SSOT §6
