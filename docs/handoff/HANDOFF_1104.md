## 2. 작업 규칙 (사용자와 합의된 방식)

- **답변은 한국어.** 설명 순서는 "왜 했나 → 무엇을 했나 → 결과 → 의미/다음", 결론 먼저. 전문 용어는 처음 나올 때 쉬운 말로.
- **노트북은 직접 편집하지 않는다.** `experiments/builders/build_*.py`를 고치고 다시 생성한다. 사용자가 Colab(A100, 새 계정)에서 실행하고 결과 파일·출력을 올려 준다.
- **사전 기준**: 모든 실험은 결과를 보기 전에 통과 기준과 해석 규칙을 `SSOT.md` §6에 고정한다. 결과를 본 뒤 바꾸면 그 사실과 이유를 §7 결정 기록에 남긴다. 미달은 미달로 적는다. 사전 기준에 없던 비교는 "사후 확인"으로 구분.
- **RAGTruth test 분할(`split=='test'`)은 열지 않는다.** S5 최종 평가에서 사용자 요청 시 단 1회. 데이터 로딩은 항상 `split=='train'`.
- **평가 세트로 모델·임계값을 고르지 않는다.** 선택은 cal-L(보정 세트), dev-L은 최종 측정만.
- **기록**: 결과·결정은 `SSOT.md`(§5 결과, §6 기준, §7 결정), `docs/PROGRESS.md`(절 추가 + "현재 위치"), 필요 시 README "현재 상태". 실험 하나 = 커밋 하나. 접두어 `feat: fix: test: exp: docs: refactor: chore:`. 커밋 전 `python -m pytest -q` 통과.
- **주간 진행보고서**: 줄글만(목록·표 없음), 문단 5~7문장, 문단 첫 문장에 결론, 1.5~2쪽, 실측 수치만, 지난 주 docx와 같은 형식(맑은 고딕). 문체 "~하였다", 단위는 "퍼센트·밀리초"처럼 한글로. 사용자가 고친 지난주 파일을 틀로 쓴다.
- 공유 드라이브의 다른 사람 파일은 승인 없이 지우지 않는다.
- 사용자는 연구적 성격보다 **동작하는 서비스**를 원한다(자기주도'프로젝트'). 남은 모델 연구는 겨울방학 자기주도연구로.

## 3. 시스템 요약

### 3.1 게이트웨이 (`hallugate/`, 약 1,400줄, 테스트 24개 — 10/21 기준)

| 파일 | 역할 |
|---|---|
| `context.py` | 요청에서 근거 문서·검증 옵션 추출, `verification` 필드 제거 |
| `splitter.py` | 스트림 → 문장 (본문 보존 불변식) |
| `judge.py` | `StudentJudge`(운영), `LexicalJudge`(테스트 전용, 수치 보고 금지). 10/21에 fp16 가중치를 fp32로 올리도록 수정(`.float()`) |
| `pipeline.py` | pass/hold, flag/cut, 앞부분 재판정(stride), 시간 기록 |
| `app.py` | FastAPI 프록시, SSE. 판정은 `choices: []` + `verification` 청크로 |

알려진 문제(미수정일 수 있음 — 확인 필요):
1. **재판정 간격이 업스트림 조각 수 기준** — 학습·임계값은 tiktoken cl100k 토큰 기준이라 불일치. Claude는 조각당 약 5토큰을 몰아 보냄.
2. 스트리밍에서 `delta.content`만 넘겨 **tool_calls·usage 청크가 사라짐**(OpenAI 호환성 버그).
3. 판정기 하나를 락으로 직렬화 → 동시 요청 시 대기열.
4. 업스트림은 OpenAI 형식만. Claude Messages API 직접 연결 없음.

### 3.2 판정기 구조

근거 문서 → 40단어 조각 → `all-MiniLM-L6-v2` 임베딩 → 판정할 텍스트와 유사한 조각 top-8(원문 순서, " ... "로 연결) → `[CLS] 근거 [SEP] 문장 앞부분 [SEP]`(최대 512토큰, 근거 쪽을 자름) → 교차 인코더 → logit(클수록 환각). 학습: RAGTruth train 3,000응답(gold-large)의 모든 2토큰 지점과 문장 끝, "그 지점이 해당 문장의 환각 시작 이후인가" 이진 분류, 학습 정답은 Claude Sonnet 재판정으로 누락을 채운 버전.
**한계**: 앞 문장 맥락을 입력에 넣지 않음, 영어 전용, 긴 근거는 일부만 봄, RAGTruth(2023년 무렵 LLM 응답)로만 평가됨.

## 5. 확정된 결정 (10/21~10/28)

- **10/21 연구 범위 축소**: 모델의 연구적 탐색 종료. 큰 판정기(large), 요약 약점, 경보 규칙·학습 목표 추가 탐색, 한국어 등은 겨울방학 자기주도연구로.
- **10/28 방향 재정의**: 연구는 멈추되 **다음 주(11/4 무렵)까지 서비스 성능 향상**(엔지니어링). 채택 여부는 cal-L 서비스 지표로만 판단, dev-L은 마지막 확인만. 후보: (1) 경보 방식 조정(예: 연속 2회 초과) — 재학습 없이 F1 점수로 계산, (2) 앞 문장을 판정 입력에 함께 넣어 재학습 1회, (3) 최신 LLM·컬렉션 조건 오경보 점검 후 임계값 재보정.
- **10/27 재생성 기능 추가(S4 이후)**: hold에서 환각 판정 문장은 내보내지 않고 버린 뒤 "근거만 사용" 지시와 함께 이어 쓰기 1회 재요청, 다시 환각이면 표시만. 표시용보다 보수적인 임계값(예: 멀쩡한 응답 5%). 문장 고쳐 쓰기·교정 모델은 여전히 비목표.
- **10/28 서비스 설계**
  - A1 본체 = 개발자용 OpenAI 호환 프록시 (데모 웹은 보류)
  - A2 **게이트웨이가 근거 문서를 관리**: 관리자·개발자가 컬렉션에 문서 등록. 요청에 근거를 직접 담는 기존 방식도 유지
  - **(b) 게이트웨이가 RAG까지**: 질문으로 컬렉션 검색 → 근거를 시스템 메시지에 넣어 LLM 호출 → **같은 근거로** 판정(LLM이 본 근거 = 판정 근거). 판정 청크에 사용 근거 조각(`evidence`) 포함
  - A3 업스트림 Claude(Messages API 변환)·OpenAI 둘 다
  - A4 배포 환경 보류 (판정기는 GPU 필요. 학교 GPU 서버 가능 여부 미확인)
  - A5 판정기·문서 저장소를 인터페이스로 감싸 나중에 분리 가능하게
  - A6 기본 정책 hold 8토큰 + flag, 재생성은 옵션, cut은 기본값 제외
  - 추천으로 제시했고 이견 없던 세부: 영어가 아니면 판정 끄고 `verified:false`, 판정기 장애 시 그대로 전달(fail-open), tool_calls는 판정 없이 통과, 저장소는 SQLite + 임베딩 배열로 시작, 컬렉션 지정은 `verification.collection`, 멀티턴 검색은 마지막 사용자 질문, 본문 로그는 기본 미저장, 접근 토큰 하나만
- **10/15** S5 최종 평가 비교 대상에 Itkin(2026)·LettuceDetect 외에 **Claude/GPT를 판정기로 직접 쓰는 방식**(비용·지연 포함) 추가.

SSOT·SPEC 반영용 문구는 10/28 인계 문서 `HANDOFF_1028.md`(사용자에게 zip으로 전달, 저장소 루트에 풀었을 것)에 있다 — 반영 여부 확인 필요.
