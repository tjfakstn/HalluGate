# 연구 계획 — 스트리밍 환각 조기 탐지 (S3 후반 ~ S5)

작성 2026-09-30. 확정된 수치와 결정은 [SSOT.md](../SSOT.md)에 두고, 이 문서는 **앞으로 할 연구의 설계**를 적는다.
실험을 시작하기 전에 해당 절의 사전 기준을 SSOT §6으로 옮겨 고정한다.

## 1. 동기 — 현재 판정기가 풀지 못한 것

S3 종단 간 측정(SSOT §5)에서 문장 판정기(student_vark)는 정확도(AUROC 0.853)와 속도(p95 20.6ms) 기준을 충족했다.
하지만 **문장이 끝나야 판정할 수 있다**는 구조 때문에 두 가지 비용이 남는다.

| 정책 | 비용 | 원인 |
|---|---|---|
| pass | 환각 문장을 잡을 때까지 약 126자가 이미 사용자에게 나감 | 판정 시점 = 문장 끝 |
| hold | 첫 글자 +447ms, 글자당 평균 +284ms | 문장이 끝날 때까지 보류 |

또 운영 임계값에서 재현율과 오표시율의 균형이 나쁘다(임계값 0에서 문장 재현율 0.22).
Main Problem인 "고정된 정확도-지연 트레이드오프"를 풀려면, 판정기가 **문장 도중에, 환각이 시작된 직후에**
판단할 수 있어야 하고, 그 판단의 **오경보율을 통제**할 수 있어야 한다.

## 2. 선행 연구와 차별점

| 연구 | 설정 | 방법 | 결과 (RAGTruth test) | 한계 |
|---|---|---|---|---|
| Itkin (2026.06), Quickest Detection of Hallucination Onset | 블랙박스, 스트리밍, 토큰 단위 | 토큰당 33차원 수작업 신호(텍스트 통계, NLI, 생성기 log-prob) → GRU → 학습된 CUSUM | 1% 오경보(ARL₀=100)에서 탐지 지연 11.5토큰 / **재현율 0.24**, HistGBM 17.9토큰 / **재현율 0.40** | 저자 스스로 "속도 향상의 대부분은 점수기에서 오며, 더 판별력 있는 신호가 1차 과제"라고 밝힘. 시스템 구현 없음 |
| Itkin (2026.07), Forecasting the Onset of Hallucination | 블랙박스, RAG, 토큰 단위 | 생존 분석(위험률), 텍스트 새로움 신호 | 3토큰 앞 예측 AUROC 0.777 | 시스템 구현 없음 |
| LettuceDetect (2025) | 근거 대조형 토큰 분류 | ModernBERT(최대 8k 토큰)로 근거+답변 전체를 읽고 토큰별 판정 | 예시 단위 F1 0.79(large) | **완성된 응답만** 판정(양방향 인코더라 미래 토큰을 봄). 스트리밍 미지원 |
| Obeso 외 (2025), Real-time entity hallucination probes | 화이트박스 | 생성기 은닉 상태 선형 탐침 | — | 생성기 내부 접근 필요 → 상용 API에 적용 불가 |

**이 프로젝트의 위치**
1. 스트리밍 조기 탐지 연구들의 병목인 **점수기의 판별력**을, 근거 문서를 직접 읽는 교차 인코더로 해결한다.
   LettuceDetect류의 강한 판정 능력을 **인과적(causal)으로**, 즉 지금까지 생성된 부분만 보고 판단하도록 바꾼다.
2. 오경보율을 **사전에 정한 수준으로 통제**하는 보정(ARL₀ 보정, conformal)을 붙인다.
3. 생성기 내부나 log-prob에 의존하지 않는다 → **어떤 상용 API 앞에도** 게이트웨이로 붙일 수 있다.
4. 실제 게이트웨이에 통합해 누출·지연·연산량을 **시스템 수준에서** 측정한다. 선행 연구는 모두 오프라인 평가에 머문다.

## 3. 연구 질문

- **RQ1 조기 탐지**: 근거 대조형 인과적 토큰 점수기는 같은 오경보 수준(ARL₀=100)에서 선행 블랙박스 조기 탐지보다
  높은 재현율과 짧은 탐지 지연을 내는가?
- **RQ2 오경보 통제**: 검증 세트로 보정한 임계값이 보지 않은 데이터에서도 목표 오경보율·오표시율을 지키는가?
- **RQ3 긴 근거**: 근거 전체를 읽는 긴 문맥 인코더가 top-k 검색 방식의 요약 과제 약점을 해소하는가? 그 지연 비용은?
- **RQ4 시스템 트레이드오프**: 위험도에 따라 재판정 간격과 보류 여부를 바꾸는 적응형 정책이 고정 정책보다
  누출·지연·연산량의 파레토 경계를 개선하는가? (Main Problem에 대한 직접적인 답)

## 4. 평가 프로토콜 (Itkin 2026과 맞춤)

- **스트림 단위**: 토큰. `tiktoken` cl100k_base로 응답을 토큰화한다. 상용 API 스트리밍 단위와 비슷하다.
  선행 연구의 토크나이저가 명시되지 않았으므로, 지연은 **토큰 수와 글자 수를 함께** 보고한다.
- **발생 시점(onset) θ**: RAGTruth 환각 구간과 처음 겹치는 토큰의 위치. 응답의 **첫 번째** 환각만 대상이다.
- **판정 시점**: 점수기는 매 s토큰마다 점수를 낸다. 점수 ≥ 임계값이면 경보.
- **오경보 ARL₀**: 환각 없는 응답들의 전체 토큰 수 ÷ 경보 수. 경보 후에는 초기화하고 계속 센다.
- **탐지**: θ 이후 첫 경보 τ. 재현율 = 탐지된 비율, 탐지 지연 = τ − θ (탐지된 것만), 검열 EDD = 미탐지는 남은 토큰 수로 계산.
- **보정**: 임계값은 **검증 분할**(S2의 90개 응답)의 환각 없는 응답에서 ARL₀가 목표값이 되도록 정한다. 평가는 dev에서 한다.
- **최종 비교**는 S5에서 RAGTruth test를 **1회** 열어 한다. dev 결과와 선행 연구 test 수치의 비교는 참고용이다.

## 6. 성공 기준 (잠정 — 각 실험 시작 전에 SSOT §6에 고정)

| 항목 | 기준 | 근거 |
|---|---|---|
| RQ1 | dev에서 ARL₀=100일 때 재현율 ≥ 0.40, 탐지 지연 ≤ 17.9토큰 (도전: 재현율 ≥ 0.50, 지연 ≤ 11.5토큰) | 선행 연구 최고치 수준 |
| RQ1 보조 | 문장 단위 AUROC ≥ 0.85 (문장 판정 능력을 잃지 않을 것) | student_vark 0.859 |
| RQ2 | 보지 않은 데이터에서 실제 오경보율 ≤ 목표 + 0.02 | 보정의 의미 |
| RQ3 | RAGTruth 요약 AUROC +0.03 이상, 재판정 1회 p95 ≤ 50ms (T4) | 요약 약점, 실시간성 |
| RQ4 | 게이트웨이에서 누출 p50 ≤ 63자(현재 126의 절반) **그리고** hold 첫 글자 추가 지연 ≤ 224ms(447의 절반) | S3 기준선 |

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| T4 메모리로 긴 문맥(4k) 학습이 어려움 | 2k로 시작, 기울기 누적·혼합 정밀도. 안 되면 top-k 검색 + 긴 창 절충 |
| 재판정마다 근거 전체를 다시 인코딩하는 비용 | 재판정 간격 s 조절, 위험도 기반 간격(E5)이 곧 해결책이자 연구 대상 |
| 발생 직후 몇 토큰만으로는 정보가 부족해 조기 탐지가 원리적으로 어려움 | E1에서 "문장 끝까지 기다릴 때 대비 줄일 수 있는 폭"을 먼저 측정해 기대치를 현실적으로 설정 |
| 선행 연구와 토크나이저·분할이 달라 직접 비교가 부정확 | 토큰·글자 수 병기, 최종 비교는 test에서, 차이를 한계로 명시 |
| dev 반복 사용으로 인한 과적합 | 임계값은 검증 분할로 보정, test는 S5에 1회 |

## 8. 10/7 수정 계획 — 학습 목표를 평가 목표에 맞추기

**왜**: E4-lite(시드 3개)와 E5-lite(게이트웨이)에서, 앞부분 학습은 AUROC와 탐지 지연은 안정적으로 개선했지만 엄격 재현율(발생 전 경보 1회면 실패)은 올리지 못했다.
지금 학습은 잘린 위치마다 독립 이진 분류이고, 평가는 "발생 전에는 조용하고 발생 직후 울리는가"라는 **순차적** 목표다. 이 불일치가 병목이다.
또 재판정을 자주 할수록 나빠지는 현상은 반복 검사로 오경보가 누적되는 문제로, 경보 규칙이 다뤄야 한다.

| 단계 | 내용 | 비용 | 시기 |
|---|---|---|---|
| **R0** | 근거 문서가 겹치지 않는 cal-L·dev-L(각 약 1,600 응답, 환각 약 750) 구축, 기존 dev 오염 측정, 모든 판정 지점 점수 궤적 저장 | T4 약 1시간 | 10/7~ |
| **R2** | 순차 판정 규칙: CUSUM, 점수 궤적을 보는 작은 학습 규칙. **다음 판정 시점(가변 재판정 간격)** 도 같이 결정 — 점수가 오르면 자주, 낮으면 드물게. 선행 연구(Itkin 학습형 CUSUM 0.24)와 직접 비교 | CPU (R0 궤적 사용) | ~10/20 |
| **R3** | 오경보 보장 보정(conformal risk control): cal-L로 "멀쩡한 응답 표시율 ≤ α"를 유한 표본 보장 | CPU | ~10/20 |
| **R1** | 발생 시점 학습: 문장 토큰 위치별 점수를 한 묶음으로, 이산시간 위험률(hazard) 손실 또는 발생 전 최고 점수 < 발생 후 점수 순위 손실. 응답 토큰에 인과 마스크를 씌운 크로스 인코더로 한 번의 순전파에 모든 위치 점수 | T4 수 시간 | 10/21~11/17 |
| R4·R5 | 앞 문장 맥락 포함, 긴 문맥(요약 약점) | — | 후순위 |

사전 기준 초안(각 실험 시작 전에 SSOT §6에 고정, dev-L·시드 3개 기준)
- R2: 같은 판정기·같은 ARL₀에서 엄격 재현율이 임계값 규칙보다 시드 평균 +0.05 이상, 지연 증가 ≤ 3토큰
- R1: 시드 평균 엄격 재현율 ≥ E2 시드 평균 + 0.05, 지연 ≤ 9토큰, 쌍체 부트스트랩 구간이 0을 포함하지 않음
- R3: dev-L에서 실제 표시율 ≤ α가 보장 수준대로 성립

위험: 양방향 사전학습 모델에 인과 마스크를 씌우면 초기 성능 하락 / 근거 검색이 앞부분마다 바뀌는 현재 방식과 한 번의 순전파 방식의 정합 / dev-L도 RAGTruth train의 일부(같은 생성 모델·작성 지침)라 최종 일반화 주장은 S5 test로만
