hallugate

내 사용 현황시작 안내데모

hallugate는 LLM API 앞에 두는 검증 게이트웨이입니다. 지금 쓰는 OpenAI 호환 코드에서 주소와 헤더만 바꾸면, LLM 답이 흘러나오는 동안 문장마다 근거 문서와 맞춰 보고 근거와 어긋나거나 근거에 없는 문장(환각)을 표시합니다. 답 본문은 그대로 전달됩니다.

현재 초대제 베타입니다. 영어 RAG 응답만 검증합니다(판정기가 영어로만 학습됨). 영어가 아니면 본문은 그대로 전달하고 검증 결과만 verified: false로 알립니다. 서버가 쉬고 있으면 첫 요청에 20초 정도 걸릴 수 있습니다.

1. 필요한 것

  • 게이트웨이 키 hg_... — 운영자에게 받습니다. 헤더 x-hallugate-key로 보냅니다
  • 내 LLM API 키 — OpenAI 또는 Anthropic. 게이트웨이는 고른 업체에만 전달하고 저장·기록하지 않습니다
  • 업체 선택 — 헤더 x-upstream: openai 또는 anthropic

2. 연결 (OpenAI Python SDK)

from openai import OpenAI

client = OpenAI(
    base_url="/v1",
    api_key="<내 OpenAI 또는 Anthropic 키>",
    default_headers={"x-hallugate-key": "hg_...", "x-upstream": "openai"},   # Claude면 "anthropic"
)

document = "Hanbit Robotics was founded in 2011 in Daejeon ..."   # 검색한 근거 문서 (영어)
stream = client.chat.completions.create(
    model="gpt-4o-mini",                                            # Claude면 예: "claude-sonnet-5-5"
    stream=True,
    messages=[{"role": "user", "content": f"<context>{document}</context>\n\nHow did the company do in 2023?"}],
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:            # 본문: 평소와 똑같이 옵니다
        print(chunk.choices[0].delta.content, end="")
    v = getattr(chunk, "verification", None) or (chunk.model_extra or {}).get("verification")
    if v and v.get("kind") == "sentence" and v.get("hallucinated"): # 판정: choices가 빈 별도 청크로 옵니다
        print(f"\n[환각 의심] {v['text']}")

근거는 메시지 안 <context>…</context> 태그로 넣거나, 메시지에 넣지 않고 extra_body={"verification": {"context": document}}로 따로 줄 수 있습니다. 근거가 없으면 검증하지 않고 그대로 전달합니다.

curl

curl /v1/chat/completions \
  -H "x-hallugate-key: hg_..." -H "x-upstream: openai" \
  -H "Authorization: Bearer $OPENAI_API_KEY" -H "content-type: application/json" \
  -d '{"model": "gpt-4o-mini", "stream": true,
       "messages": [{"role": "user", "content": "How did the company do in 2023?"}],
       "verification": {"context": "Hanbit Robotics was founded in 2011 ..."}}'

3. 받는 것

  • 본문 청크: OpenAI 형식 그대로
  • 판정 청크: choices: []이고 verification 필드가 있는 청크. 문장마다 {"kind": "sentence", "text", "score", "hallucinated", "start", "upto"}(문장이 끝나기 전 앞부분 경보는 "kind": "prefix"). 기존 OpenAI 클라이언트는 이 청크를 무시하므로 코드가 깨지지 않습니다
  • 검증 중단: {"kind": "unverified", "verified": false, "reason": "non_english" | "judge_timeout" | "judge_error"} 한 번 — 이후 본문은 판정 없이 계속 전달됩니다

4. 옵션 (verification)

필드값뜻
context문자열 또는 목록근거 문서. 없으면 메시지의 <context> 태그를 씁니다
modehold | pass | offhold: 문장을 판정한 뒤 내보냄(기본) · pass: 바로 내보내고 판정은 뒤따라옴 · off: 검증 안 함
actionflag | cutflag: 표시만(기본) · cut: 환각 문장에서 응답을 끊음
trimtrue 또는 {"top_k": n}LLM 비용 절감: 긴 근거에서 질문과 관련된 조각 8개만 LLM에 보냅니다(실험에서 입력 토큰 약 48% 절감, 답 품질 유지). 이때 근거는 context 필드로 주세요
collection컬렉션 이름미리 올린 문서에서 근거를 찾아 넣습니다(아래)
post_checktrue실험 기능: 답이 끝난 뒤 Claude로 한 번 더 검증(하루 한도 있음)

5. 문서 올려 두고 쓰기 (선택)

curl /v1/collections/kb/documents -H "x-hallugate-key: hg_..." \
  -H "content-type: application/json" -d '{"doc_id": "about", "title": "About us", "text": "..."}'

그다음 채팅 요청에 "verification": {"collection": "kb"}를 주면 질문으로 관련 조각을 찾아 LLM에 넣고 같은 조각으로 검증합니다. 컬렉션은 내 키에만 보입니다.

6. 요청 기록 남기기 (디버깅용, 선택)

프롬프트·RAG를 다듬을 때, 요청에 헤더 x-hallugate-trace: 1을 붙이면 그 요청만 상세 기록이 남습니다. 내 사용 현황의 "요청 기록"에서 LLM에 실제로 간 메시지(컬렉션 근거가 들어간 뒤), 판정에 쓴 근거, 문장별 판정 점수, 토큰·지연을 볼 수 있습니다.

client.chat.completions.create(..., extra_headers={"x-hallugate-trace": "1"})
# 응답 헤더 x-hallugate-trace-id 로 콘솔의 기록을 찾을 수 있습니다
# API: GET /v1/traces, GET /v1/traces/{id}, DELETE /v1/traces/{id}, DELETE /v1/traces

기록은 내 키로만 볼 수 있고 7일 뒤(또는 키당 200개를 넘으면 오래된 것부터) 지워집니다. 요청 헤더(LLM 키 포함)는 저장하지 않습니다. 운영 중인 실사용자 데이터에는 꼭 필요할 때만 켜세요.

7. 한도 · 사용량 · 개인정보

  • 기본 한도: 분당 30요청, 동시 4개, 근거 5만 자, 하루 2단 검증 50회. 넘으면 429(retry-after) 또는 413
  • 내 토큰·추정 비용·검증 결과는 내 사용 현황에서 봅니다(API: GET /v1/usage?window=30d). 월 예산을 받았으면 응답 헤더 x-budget-used로 사용률이 옵니다
  • LLM 키는 어디에도 기록하지 않습니다. 질문·근거·응답 원문은 위 요청 기록을 켠 요청만 7일 남고, 그 밖에는 시간·토큰 수·판정 수 같은 숫자만 30일 보관합니다. 키 전체 데이터 삭제는 운영자에게 요청하세요
